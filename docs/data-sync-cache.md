# 数据同步与缓存原则

## 数据分类

系统区分两类数据，二者不能共用同步模型：

| 类型 | 典型内容 | 本地职责 | 远端职责 |
|---|---|---|---|
| 可写工作区 | 个人资料、个人事件、收藏、订阅关系、偏好 | 保存远端基线与未同步修改，支持离线读写 | 保存可分享的标准数据 |
| 只读资源 | 市场目录、外部 Feed、他人资料、搜索结果 | 缓存内容并复用已有结果 | 作为内容来源，不接受工作区同步 |

市场、内容读取、搜索和个人同步是独立能力。它们可以来自不同服务，也可以分别更换数据源；页面不依赖 GitHub、Issue 或具体存储服务。

## 可写工作区

页面始终面向同一套本地读写语义，不感知网络同步。未登录时使用完整的本地工作区，不产生云端同步任务；登录并选择远端资料后，才建立同步关系。

绑定同步端点后，远端文档是同步基线，本地保存最近取得的基线缓存和尚未提交的 patch。页面展示的是“远端基线缓存 + 本地 patch”，因此离线编辑立即可见，已在本机加载的数据无需等待网络。

patch 按业务项覆盖：个人资料按字段或集合项处理，事件按事件 ID 整体处理，删除也是一种 patch。同一项连续修改只保留最终结果；若修改恢复为远端值，则不再视为待同步修改。

## 同步语义

每次同步先取得最新远端文档，再应用本地 patch，最后将结果写回远端。规则如下：

- 本地未修改的内容始终采用远端最新值。
- 本地修改过的字段或事件始终以本地 patch 为准。
- 本地和远端修改不同数据时，两边结果同时保留。
- 写入前远端再次变化时，重新取得远端并重放同一批 patch。
- 同步成功只确认本轮 patch；同步期间产生的新修改留到下一轮。
- 网络、限流或临时失败不会丢弃本地 patch，恢复后继续同步。

当前不解决多设备同时修改同一业务项的确定性合并。后同步设备的本地 patch 可以覆盖远端同一项。

GitHub 作为同步端点时，只把目标 `ahead.yaml` 视为数据源。设备 ID、修改历史、同步状态和冲突元数据不得写入仓库；仓库中的其他文件和目录不属于同步范围。

## 缓存与地址

所有只读页面共享同一份资源缓存和请求结果。读取优先返回本地内容，再按新鲜度在后台更新；相同来源和版本不得重复下载正文。

完整 Feed 与搜索产生的局部结果必须区分。局部结果可以补充缓存，但不能覆盖完整 Feed，也不能据此判断远端事件已被删除。

已经加载且被收藏、置顶或订阅的内容应保留供离线读取；普通缓存可按容量和最近使用情况淘汰。搜索和市场状态只保存引用与浏览状态，正文继续复用资源缓存。

资源身份与读取位置相互独立。事件首次同步前使用本地地址；进入远端基线后使用稳定的远端地址。之后即使存在未同步编辑，页面仍从本地基线与 patch 读取，不因地址变为远端而重新下载。

缓存按登录身份隔离，账号切换后旧身份的请求和结果不能进入新身份。公开访客缓存可以在登录后复用，但私密同步数据不能进入公开资源缓存。

## 典型场景

- **离线创建或编辑**：修改保存为本地 patch，页面立即更新；联网后自动同步。
- **仅远端更新**：本地没有对应 patch，刷新后直接采用远端内容。
- **同项同时变化**：本地存在 patch 时，本地结果覆盖远端同一字段或事件。
- **远端删除**：本地没有修改时随远端消失；本地仍有该项 patch 时按本地结果重新写入。
- **本地删除**：删除 patch 应覆盖远端对同一项的修改。
- **同步中继续编辑**：已提交的一批修改被确认，新产生的修改继续留在本地。
- **重新打开应用**：先展示本地工作区和缓存，再恢复后台刷新与同步。

这些原则优先保证本地操作即时、离线内容可用、远端分享数据干净，以及数据来源可以独立替换。
