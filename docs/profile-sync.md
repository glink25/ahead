# 多个人资料与自动同步

## 用户流程

登录身份与个人资料分开：一个 GitHub 账号可以使用多个公开或私密的 UserData 仓库。主动登录进入资料选择；重新打开应用恢复该账号上次使用的资料。资料列表扫描具有写权限仓库的 `ahead.yaml`，其他路径可通过手动添加连接。新建资料支持名称、简介和可见性。我的页标题与设置均提供切换入口。

未登录可使用本机资料与 Studio。选择登录资料后，访客数据自动合入，包括所选资料为公开的情况。迁移前保存本地备份。不同资料之间不自动复制内容。公开资料及其个人事件会写入公开仓库。

Studio 保存首先完成本机事务，再返回事件详情；支持编辑、删除及从历史恢复。个人事件写入关联的 Personal Feed，UserData 的 `io.ahead.personal-feed` 扩展和订阅记录指向此 Feed。新 Feed 与资料的可见性一致，不修改既有仓库的可见性。

## 持久化边界

`packages/sync` 提供与 GitHub 无关的记录合并、事务、集合校验和订阅接口。`apps/web/src/data` 实现 IndexedDB、OEF 投影、资料选择和远端调度。业务功能通过 `mutateProfile`、`saveEvent` 等本地接口写入；新增可同步集合时注册校验器及 OEF 投影即可复用调度。

IndexedDB `ahead-workspaces/state` 保存所有资料，每次更新通过一个 readwrite 事务同时落盘记录和待同步操作。事件、收藏、隐藏、置顶、订阅、兴趣、备注、个人修改及资料设置按资料隔离。BroadcastChannel 通知其他标签页重新读取；支持 Web Locks 的浏览器按账号串行执行同步。旧版 `ahead-local-profile` 只迁移一次并保留备份。

## 同步与冲突

本地修改后延迟两秒同步，持续编辑最多等待十五秒；联网、窗口聚焦及前台定时检查也触发同步。每次请求绑定账号与目标资料；切换身份中止旧任务的后续请求。切换资料不会把已发出的修改写入新资料。

每条记录携带逻辑时间、设备标识和操作 ID；同一记录以版本顺序确定结果，保留最近二十个历史版本。删除写入墓碑，恢复产生新版本。待发送操作压缩为每条记录最新修改，发送期间产生的新修改不被旧请求清除。

标准 OEF manifest 与 `.ahead/<encoded-manifest-path>.sync.json` 在同一 Git commit 中写入。读取阶段识别外部直接修改 manifest 的内容并转换成新版本。提交以预期 HEAD 为条件，冲突重新读取合并；响应丢失后重新读取，不重复提交相同结果。新仓库使用持久化名称与标记，重试可找回已创建仓库，同名冲突自动另取名称。

网络或限流失败指数退避，遵守 Retry-After 和限流重置时间。认证失效、权限问题、不合法数据或可见性变化保留本地修改，设置中展示重试入口。历史、诊断、暂停同步也在设置中提供。

## 离线与兼容范围

生产构建预缓存应用外壳与懒加载资源。首次在线缓存完成后，断网刷新仍可编辑保存；恢复网络后继续同步。Service Worker 不缓存认证或私人仓库响应。本机 IndexedDB 保存资料，退出登录不删除资料。

目前个人事件同步写入内嵌 `events` 的标准 Feed；已有 `eventsGlob` Personal Feed 会提示格式不支持并停止写入。外部改变已有 Personal Feed 关联时停止同步，避免无意覆盖关联或混入另一个 Feed。旧版本客户端不理解同步元数据时，只能读取标准 OEF 当前状态，不能参与历史合并。

## 验证

- `pnpm test`：仓库单元测试，含事务失败、合并/墓碑、历史和 outbox 压缩、远端外部编辑、提交重试及 GitHub 404 回归。
- `pnpm test:e2e`：桌面与移动端交互、离线本地 CRUD、多资料同步与隔离、多标签页写入。GitHub API 由测试模拟，不修改真实账号。
- `pnpm --filter @ahead/web test:offline`：独立构建生产资源，验证 Service Worker 就绪后断网刷新、打开 Studio、保存和再次读取。
